# 高效制作：先验证，再切片，最后渲染

适用于多零件免胶模型和单盘逐色组交付。保留真实几何、装配、切片验证；通过减少返工和复用不变结果提速。只改文字或图片时不重做网格；改打印机/喷嘴/材质/接口时必须重做受影响的检查。

## 本次复盘

钻臂工程车发生过：共面接触造成5个连通体；C夹与梁重复切割造成13条非流形边；中央支架/钻头颈杆侵占夹环；保险杠与车身54.86mm³穿插。原build.py包含40样本Cycles渲染，验证前就渲染；修改后重复整套构建。首次Blender未获得Python异常回执，增加日志才定位失败。只读记录这些实际问题，不捏造旧流程端到端耗时。

## 默认制作顺序

1. **结构表一次确定**：零件ID、颜色组、配合对象、自由度、开口/进入方向、打印姿态、机型、材料、间隙、最薄壁和物理验证状态。没有原件尺寸时明确是照片重建。把隐藏接口不确定性和可视外形分开处理。
2. **接口先做小样**：复用本机已记录的参数模板；标注material/nozzle/print_orientation和physical_fit_verified。先在Blender生成定位销、C夹、轮轴、对应母孔/挡边及颈杆/支架邻近结构，检查封闭性、连通性、正体积和静态进入空间，再画装饰。不能只检查孤立C圈，忽略梁和颈杆。复用未实测卡扣仍需真实试打。
3. **主几何阶段无渲染**：Boolean EXACT后立刻检查每件；错误报告包含零件ID和局部原因。同一部件内部真实重叠后融合，避免共面接触；C环先与梁合并，再一次减去孔和C口，减少重复布尔边界。保留完整精度网格检查，不降低校验强度换速度。
4. **先装配审核**：AABB过滤不可能相交的组合，再做候选对实体相交。按真实进入方向检查外部障碍，另外记录排除的弹性配合对和所需变形。失败时定位、修改、重查受影响零件与相关配合；不要先正式切片再发现静态穿插。
5. **生成真实接口试打盘**：裁切同一版本真实零件/邻近结构，保持与主盘同方向。数字试打盘可准备，不默认等待用户实际打印才继续做其他可独立工作；主盘标明未实测。
6. **预检查摆盘再切片**：每色一个组对象，组内独立网格；原厂180mm床面、喷头/横杆避让参数从当前本地官方机型配置读取。先算姿态、床面Z、组间距、非最后组高度，然后CLI切片。主盘与试打盘各用不同输出目录，避免result.json串写；同一Bambu实例的CLI任务默认串行。
7. **验证成功才最终渲染**：核对native 3MF、警告和G-code三个连续组段，再渲染组装图/拆件图。只检查轮廓时用Solid/Workbench/Eevee或8–16样本小预览；最终图依清晰度使用适量Cycles采样，不能以低清预览替代成品。图上编号/文案变化只更新叠加图，不重渲染几何。
8. **按版本一次归档**：D:\AI3D建模\作品名\机型-版本，正式文件以tmp验证后Move-Item提交。不要为每个文件反复启动GUI；可用一次PowerShell会话执行一组已逐个检查的文件移动，保留备份，不批量删除。

## 阶段依赖与缓存

建议拆为 geometry → assembly-audit → trial-input/trial-slice；assembly-audit → main-input/main-slice；通过后 render-assembled/render-parts → annotate/docs → publish。有明确需求时由调用方生成只包含需要分支及其依赖的计划。当前--until执行顺序前缀，不自动裁剪祖先分支。

使用 [../scripts/run_pipeline.py](../scripts/run_pipeline.py) 运行项目计划。它执行argv列表（不拼shell），每阶段强制验证命令、输入和输出清单，记录日志/耗时。缓存键包含阶段配置、声明输入文件哈希、上游输出哈希、运行器自身哈希；输出也需与上次已验证哈希一致。失配时重跑，旧输出移入工作目录.pipeline/history后再执行，防止CLI退出0但读取旧结果。命令失败、输出缺失或验证失败立即阻断后续阶段，不注册后台任务，不发送真实打印。

```text
python scripts/run_pipeline.py PROJECT_PIPELINE.json
python scripts/run_pipeline.py PROJECT_PIPELINE.json --until assembly-audit
python scripts/run_pipeline.py PROJECT_PIPELINE.json --force
```

计划中的workspace使用独立项目/版本目录；输出只能是该目录内明确文件。inputs要包含所有实际依赖：构建及验证脚本、参数JSON、外部网格、机型/工艺/耗材及G-code模板、外部工具可执行文件。不能漏掉某个参数文件后把缓存当作有效。固定新内容时先保存输入文件，再执行。

每个stage至少包含id、inputs、outputs、command、validate。depends_on只能指前面已通过的阶段；不允许多个stage写同一输出文件。timeout_seconds默认900，可按实际操作设定。cwd默认workspace，自定义时用绝对路径。

```json
{
  "workspace": "D:/AI3D建模/作品名/工作-v2",
  "stages": [{
    "id": "geometry",
    "inputs": ["build_geometry.py", "validate_geometry.py", "params.json", "C:/Program Files/Blender Foundation/Blender 5.2/blender.exe"],
    "outputs": ["model.tmp.blend", "parts_manifest.json"],
    "command": ["C:/Program Files/Blender Foundation/Blender 5.2/blender.exe", "-b", "--python-exit-code", "1", "--python", "D:/AI3D建模/作品名/工作-v2/build_geometry.py"],
    "validate": ["C:/实际Python路径/python.exe", "D:/AI3D建模/作品名/工作-v2/validate_geometry.py"]
  }]
}
```

这是结构示例，路径、产出和验证脚本必须改成实际项目。验证应读取manifest、STL/网格、JSON成功标记与结果文件，不能仅检查文件存在。Blender使用--python-exit-code 1；捕获异常的包装脚本也必须输出失败状态或退出非零，不能吞掉异常。Bambu还要检查result.json return_code和新导出的原生3MF，不把启动窗口当作成功。

## 复用与失效边界

| 改动 | 重跑范围 |
|---|---|
| 文案、编号位置 | annotate/docs及发布；图本体不变 |
| 灯光、材质外观、相机 | 对应渲染和图文；打印材质参数改变是另一项 |
| 某个机械接口 | 几何、相关装配/试打、受影响切片与展示 |
| 摆盘、颜色组、打印顺序、机型、喷嘴、工艺/耗材 | 受影响的预检和实际切片/G-code验证；机型/材料影响接口时也重审接口 |
| 没有变化 | 核对输入/输出哈希，复用上次已验证结果 |

当前运行器是**阶段级**缓存，未实现按零件内部函数的自动局部重建。需要进一步提速时把高成本模块拆为独立脚本和明确产出，再接依赖图；不要声称仅修改一个销已自动只重建该销。重复轮子可从一次审核的母网格复制四个部件，保持独立ID/姿态和装配检查。

## 已测与未测

2026-10-01本机真实工程车：无渲染几何18.02s，装配/真实试打件生成6.52s，合计24.54s（阶段计时，不含最后回执）。输入不变时哈希复核0.48s；包括回执写入2.19s。11个生产STL与原交付哈希完全一致。运行器输入失效、依赖分支、输出篡改、失败阻断、退出0但输出缺失、验证失败、恢复及路径限制共9项行为测试通过。

这不是旧端到端与新端到端比较，不覆盖新创意、人工判断、渲染、切片或实际打印，不能换算总体提速百分比。以后记录各阶段执行/缓存命中、重建次数、切片次数、错误类别和首次正确通过率，再判断瓶颈。打印耗时另行优化：姿态/减少支撑/删无功能装饰优先，改变层高、墙数或速度时重新验证，不能为制作提速牺牲卡扣强度。
