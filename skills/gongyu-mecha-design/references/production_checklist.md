# 接口学习与真实小样

当前源库尚未建立跨型号通用接口标准。每个尺寸必须引用源SHA、网格/零件、单位、测量位置及朝向。不得从整体包围盒直接推算配合槽宽；STL没有单位，需要结合同型号3MF或已知尺度核对。

207的实际形状可学习宽收腰连接与叉形分段臂，但“卡扣”可能承担定位/摩擦/防脱的不同职责。先截取配对剖面，量凸块宽、颈部厚、槽口、锁定腔、轴肩与孔，再判断装入方向和是否需弹性形变。无这些证据不填“全套标准卡扣0.xxmm”。原作者照片能支持成品形态，不能支持当前耗材寿命或跨型号互换。

## 设计与验证记录

1. 零件A/B、承力方向、活动自由度、定位与止退方式。
2. 源接口剖面与关键尺寸；源型复刻不单独改孔、缩轴肩或替换叉口。
3. 进入/拆卸方向和邻近障碍；运动全程要检查，而不只看最终就位。
4. 打印方向、接触面、根部圆角/筋、墙层；Z弱面与开口薄臂需要专门注意。
5. 梯度间隙小样与完整轴轮；同材料、喷嘴、方向，记录插入力、白化、断裂、松脱、往复结果。
6. 小样通过后再替换正式主盘；失败接口单独修正，保留旧版与失败记录。

用户之前真实反馈过断轴/脆弱卡扣，因此必须区别“网格闭合”“静态就位”“路径检查”“实物扣合”“耐用性”。当前技能只整理形态与流程，尚没有统一实验合格参数。免胶是设计要求，不是已完成试验的结论。

# 制作验收与用户约束

在本地Blender实际建模并保存.blend与分件网格；渲染不是可打印模型。每部件检查封闭性/连通性/正体积、单位、打印朝向、Zmin真实接触面、悬空或支撑需求。源库support=0只是配置事实，不当作普遍无需支撑保证。

A1mini0.4默认；根据实际官方配置保留避让/启动结束/换料G-code。用户要求单盘同色父组依次完成、无擦料塔。组内零件同层打印，整组结束再下组；不可把独立对象随意逐个分散。无塔仍保留原厂清洗，材料变化需重新验证。

9份多色样本盘级by object覆盖全局by layer；单色夫诸22个父对象按层。这是学习原文件时的分歧，用户新作按其逐组要求重新摆盘。原库prime_tower=1，不可倒置为原作者默认无塔。碰撞/越界/悬空报警要处理，不减小原厂避让掩盖错误。

真正G-code检查每组连续打印、顺序、料槽与切换次数，不能只看设置界面。不同组数/同色组/单色文件需适配检查逻辑，不要求全部2次换色。Native导出后再次看项目差异记录与盘级覆盖；补元数据只对应真实切片配置，工艺变化必须重新切片。重开3MF核对机型、by object、塔、支持和料槽，未重开则标记GUI未验证。
