# 小猫车 v4：配对接口与验证提效

证据来自2026-10-14至15日小猫车修复，不是实物试装合格记录。来源与哈希见manifest，摘要见case-v4.json。此文不构成公羽全库通用接口标准。

## 本次有效改动
- 旧轮组为六根独立实心轴，未遵循用户要求的原型卡扣。v4从207原3MF提取底盘一体开槽轴和完整轮胎，取消六根独立轴，17件变11件。
- 使用配套轴头、轮孔台阶、锁定腔；不得只学外观，擅自削小轴肩或放大轮孔以消除预期干涉。新车体可以改轮距，但接口尺寸与原打印方向单独锁定。
- 按组件变换还原实际尺寸；记录裁切边界、拼接位置、源SHA和配对零件。拼接只发生在根部，不侵入开槽、承载面和止退面。
- 顶点接近仅是一项保真证据，不能单独证明曲面/拓扑相同。完整轮胎应比较三角面；裁切轴头应比较工作曲面或截面，区分根部允许变更区。
- 同一部件的融合有实际重叠，布尔后立即检查单连通、封闭、正体积。v4圆柱填旧孔后出现1079条非流形边；改有明确重叠的实体填充才通过。重复顶点清理没有解决该问题，不能误记为根因已确认。

## 必需检查
1. 静态：全部配对件与邻近障碍；每个非零穿插明确归因，未知穿插阻断交付。
2. 压入：保留原轴头真实干涉曲线。仅允许在有证据的局部弹性区域豁免刚体碰撞，记录范围、峰值、采样步长。不得删掉整个配对件。
3. 转动：记录轴心、角度步长、所有障碍。15度抽样通过不能写成连续全角度数学证明。
4. 防脱：沿拔出方向探测止退面接触，不能把摩擦紧配叫轴肩锁止。刚体止退接触不证明抗拔力。
5. 实物：同喷嘴、耗材、朝向的小样检查白化、断裂、转动、松脱。未试装保持physical_fit_verified=false；源作者成功不等于新件成功。
6. 文件：Blender→导出网格→摆盘3MF→原生切片3MF逐段比较，确认三角面、位置及贴床面，核对G-code校验和。
7. 打印：同色部件归一个父对象，按对象完成三个颜色组；实际G-code检查连续组序与换色。无擦料塔仍保留原厂冲刷；延时摄影提示与碰撞警告分别报告，不写“零警告”。

## 减少重复计算
- 拆成source→geometry→static→tail/body→wheel-1…wheel-N→face→placement→slice→package→render阶段，采用现有run_pipeline.py，每个阶段有独立JSON输出和验证命令。
- 每个轮位完成就原子写结果；失败保留前面阶段。记录耗时、采样计数和最后成功步骤。长步骤给进度，不因慢而反复终止重跑。
- 缓存键包含参与零件几何、组件变换、装配路径、轴心、弹性豁免范围、采样步长、检查脚本、Blender版本；切片还含官方配置、Bambu版本和摆盘。改变任何相关输入使对应阶段失效。
- 先用包围盒排除明显不相交。局部精确碰撞只能裁去运动全过程不可能触及的空间，保存裁切范围与运动包络包含证据；不可只按最终姿态裁切。
- 相同六轮可以复用局部接口结果，前提是配对曲面和刚体变换等价有证据。每站仍检查车壳、邻轮、轮罩等局部环境。
- v4实施未实现持久化逐轮缓存，没有可靠前后耗时基准，不声称已实现倍数提速。以上是后续执行规范；需用阶段运行记录验证收益。
